移除有序数组中的重复元素题目考察双指针的基本用法，快指针逐个读取元素并记录相同元素个数，慢指针逐个写入元素并保证相同元素不超过2个。

多数元素题目有两个解答思路。一个是先完成数组排序，然后逐个读取元素并计数，当找到某个元素个数大于数组长度的一半时，返回该元素；另一个思路是逐个读取数组元素并分别计数，读取完成后遍历哈希表找到个数足够多的元素。

旋转数组题目给出三个解答思路。
第一个是开辟长度为`k`的临时空间，将后`k`个元素写入临时空间，然后前`length - k`个元素平行后移，最后将临时空间中的`k`个元素写入数组头部。
第二个是逐个移动法，将位于`i`处的元素*向后*移动到`i+k`处(实际位置是`(i+k)%length`)，将`i+k`处的元素移动到`i+k+k`处，经若干次操作位置指针可能又回到`i`处，此时再由`i+1`处开始，移动到`i+1+k`处...，经若干轮(实际总轮次为`gcd(k, length)`，实际总移动次数为`length`，即每个位置上的元素都移动过)，完成数组旋转操作。
第三个是三次反转法，先将数组整体反转，`[a, b, c, d, e]`反转为`[e, d, c, b, a]`，然后将前`k`个元素反转，这样前`k`个元素就恢复原有的顺序并且来到数组前，再然后将后`length-k`个元素反转，这样后面的元素也恢复原本的顺序，三步操作完成后，数组完成`k`个元素的旋转。

找出成绩提升的学生题目中，回顾窗口函数`ROW_NUMBER() / FIRST_VALUE() / LAST_VALUE()`的基本用法。其中问题点在于，如果在`OVER()`子句中使用`ORDER BY`，默认窗口范围是`RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`，这导致`LAST_VALUE`只能看到**当前行**，需要将窗口范围显式声明为`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`(完整语句为`LAST_VALUE(col) OVER (PARTITION BY pcol ORDER BY ocol ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLLOWING)`)来整个分区的数据都在窗口内。(`OVER()`子句中不使用`ORDER BY`，默认窗口范围就已经是`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`)。

> + [3.5. Window Functions](https://www.postgresql.org/docs/current/tutorial-window.html)
> + [4.2.8. Window Function Calls](https://www.postgresql.org/docs/current/sql-expressions.html#SYNTAX-WINDOW-FUNCTIONS)
> + [9.22. Window Functions](https://www.postgresql.org/docs/current/functions-window.html)

DNA模式识别题目中，主要回顾`CASE WHEN`语法，`CASE WHEN pred1 THEN x WHEN pred2 THEN y ELSE z END`。

分析组织结构题目中，全新接触递归查询的相关知识，通过`WITH RECURSIVE t AS ( SELECT xxx FROM t UNION SELECT xxx FROM t)`创建可递归查询。此外应注意，可递归查询每次只将**本轮迭代**的结果放到临时工作表，然后使用该结果子集发起下一轮迭代，直到某轮迭代没有输出任何数据时停止。由于中间结果不保证完整，因此在迭代步骤中不允许使用聚合函数。关于`t`，若使用`UNION`则在每轮迭代和最终合并时都执行数据去重，使用`UNION ALL`则只进行数据合并，完全不去重。参考文档：[7.8.2. Recursive Queries](https://www.postgresql.org/docs/18/queries-with.html#QUERIES-WITH-RECURSIVE)
